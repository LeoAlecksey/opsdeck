# Участие в OpsDeck

Спасибо, что хотите помочь! Ошибки, идеи и pull request'ы приветствуются.

> *English:* issues and PRs in English are welcome too. Short version: fork → branch → `npx tsc`, `npm test`, `npm run test:ui` and `cargo test --lib` pass → PR to `dev` with a description of what and why.

## Сообщить об ошибке или предложить идею

- **Ошибка** — [новый issue «Ошибка»](https://github.com/LeoAlecksey/opsdeck/issues/new/choose): версия OpsDeck (⚙ → Обновления), ОС, шаги, что ожидали и что получилось. Очень помогает журнал: ⚙ → Журнал → «Показать ошибки и зависания» или «Открыть папку» и приложить файл. **Перед отправкой уберите из журнала адреса, имена хостов и всё, что считаете чувствительным.**
- **Идея** — issue «Предложение»: какую задачу решает, как вы это себе представляете.
- **Уязвимость** — не в issue, а приватно: см. [SECURITY.md](SECURITY.md).

## Как прислать изменения

1. Сделайте форк и ветку от `dev`: `git switch -c fix/terminal-tabs`.
2. Соберите и запустите (нужны Rust stable и Node.js 20+, на Linux — системные библиотеки из [README](README.md#сборка-из-исходников)):
   ```bash
   npm install
   npm run tauri dev
   ```
3. Перед PR должно проходить без ошибок:
   ```bash
   npx tsc                                  # типы TypeScript
   cd src-tauri && cargo check && cargo test --lib
   cd .. && npm test && npm run test:ui   # тесты интерфейса: vitest и Playwright (сам поднимет vite)
   ```
4. Откройте PR в ветку `dev` (в `master` попадает только то, что уходит в релиз). Заполните шаблон: что изменилось и зачем, как проверяли. Сборку и проверки для PR в `dev` мейнтейнер запускает вручную после просмотра кода.

Один PR — одна задача: так его проще проверить и быстрее влить. Большие изменения лучше сначала обсудить в issue.

## Как устроен код

- `src-tauri/src/*.rs` — бэкенд на Rust (Tauri 2): по модулю на раздел (`k8s.rs`, `db.rs`, `notes.rs`, `tasks.rs`, `ai.rs`, …). Команды для интерфейса — функции с `#[tauri::command]`, регистрируются в `lib.rs`.
- `src/modules/*.ts` — интерфейс без фреймворков: по модулю на раздел (`mountXxx(root)`), общие стили — `src/styles.css`.
- `src/modules/help.ts` — встроенная справка (кнопка **!** в разделах): если меняете поведение или горячие клавиши — обновите и её.

## Стиль

- Пишите так же, как написан соседний код: те же имена, тот же уровень комментариев (комментарий — про «почему», а не «что»).
- Тексты интерфейса пишутся на русском, коротко и по делу; английский перевод — в `locales/en.json` (ключ — русская строка, `{}` — подстановка). После изменения текстов: `npm run i18n:missing` покажет, что не переведено, `npm run i18n:check` проверит, что перевод ничего не ломает (проверка есть и в CI). Справка: русская — `src/modules/help.ts`, английская — `src/modules/help-en.ts`.
- Rust: `cargo fmt`; без `unwrap()` там, где ошибку может вызвать пользователь или сеть — верните понятное сообщение.
- Ничего, что работает с паролями, токенами и kubeconfig, не пишите в журнал и не отправляйте наружу.
- Новые зависимости — только если без них никак; в описании PR объясните, зачем.

## Безопасность

PR, которые трогают CI, выпуск релизов и обновления, работу с паролями и секретами, запуск команд, зависимости или ссылки автора, автоматически получают метку «⚠ безопасность» и проверяются владельцем особенно внимательно (см. `.github/CODEOWNERS`). Ссылки автора на донат и Telegram защищены проверкой `npm run check:links`: изменить или добавить другие ссылки на оплату, кошельки или Telegram в PR нельзя.
